## 1. 项目目的与需求

**立项**：2026-08-14。**维护**：Owen（区恩铭）一人。

**目标**：实时语音 + 自然对话（像正常聊天）+ 综合情绪识别；后期接机器人本体与传动。

**一条硬需求，决定了整个架构选型**：

> **「派活 → 逐字播报」** —— 助手执行完任务后，必须能把结果**一字不差**地念出来。

正是这条需求**证伪了端到端双工路线**（端到端模型结构上做不到忠实逐字朗读，见 §9）。

**隐性验收口径**（从历史对话提炼，非纸上需求）：
- 闲聊时**首音要快**（实测：闲聊 ~1s，调工具 7.7s）
- 播报中**直接开口就能打断**，不用先说"停"
- **不能凭空自言自语**（曾出现模型自导自演一段"搜索过程"停不下来）

## 3. 架构（现行 · 级联）

```
麦克风 → Silero VAD（段级信噪比门限） → SenseVoice ASR（本地）
      → 切句 + 口语规则 → Claude Code 常驻子进程（脑 = haiku）
      → sanitize（朗读前清洗） → Fish Audio TTS（云） → 扬声器
```

**为什么级联**：2026 生产主流；VoiceAgentBench 实证 **agentic 任务上级联 > SpeechLM**；且能忠实播报（§9 的硬需求）。

**并发模型**：线程 + 有界队列，**全栈阻塞式，不混 asyncio**。三个线程：`MicThread`（主线程）/ `BrainThread` / `TTSThread`，用 `utt_q`、`sent_q` 两个队列串联（见 `orchestrator.py` 顶部注释与 plan §8）。

### 音频模式（一个事实来源，别两处改）

| 模式 | 打断 | 麦克风 | 用途 |
|---|---|---|---|
| `headphones`（默认） | 🟢 自动打断 | 全程听 | 戴耳机。麦克风听不到耳机 → 无回声 |
| `speaker`（免提） | ❌ 关闭 | **播放期间不听**（半双工） | 无 AEC，必须两件事一起关，只关打断不够 |
| `speaker_aec` 🆕 | （规划中，**未实现**） | 全程听 | 软件 AEC（pywebrtc-audio）消除自己的回声后免提打断。接入方案 + P0 实测设计见 `docs/RESEARCH-AEC-20260919.md`；实测出 ERLE 数字前不要动这两行 |

由 `config.py` 的 `barge_in` / `half_duplex` 两个 property 从 `audio_mode` 派生——**这是刻意的单一事实来源**，避免两处开关打架。

### 关键机制

- **打断**：向 `claude --input-format stream-json` 写 `control_request{interrupt}` 控制帧，🟢 ~10ms 生效（收尾 `terminal_reason=aborted_tools`）
- **记忆**：`~/.jarvis/persona.md`（人工维护身份/世界事实）+ `memory.md`（脑可写）→ 合成 `~/.jarvis/system_prompt.md` → `--system-prompt-file` 注入
- **MCP 工具**：`tavily`（搜索）/ `browser`（浏览器）/ `obsidian-vault`（第二大脑，**可按需热重连**，走 `mcp_reconnect` 控制帧，不用重启脑进程）
- **元命令**：清理上下文 / 暂停监听 / 继续监听 / 连上第二大脑 / 记住 X

## 5. 怎么跑

```bash
cd ~/jarvis-voice
./jarvis.sh start --dashboard      # 耳机模式 + 仪表盘 http://127.0.0.1:8848
./jarvis.sh start --speaker        # 免提（需 JARVIS_OUTPUT_DEVICE=MacBook，否则仍走耳机）
./jarvis.sh start --fresh          # 不复用上次对话（清理被污染的链条）
./jarvis.sh status                 # 看有几个实例在跑（>1 会告警）
./jarvis.sh stop
```

**前置**：`~/.jarvis/fish.env` 里有 `FISH_API_KEY`；`claude` CLI 已登录。
**免提真生效**：必须把**输出也切到内置扬声器**，否则麦克风听不到自己，等于还是耳机。

## 6. 已验证的事实与限制（🟢 一手）

- 🟢 `control_request{interrupt}` 在 stream-json 常驻模式下**可中断**（~10ms）
- 🟢 `--system-prompt-file` 内容**真进上下文**；`--append-system-prompt-file` 同理
- 🟢 **`--bare` 下拿不到** CLAUDE.md 自动发现、auto-memory、插件钩子；`--add-dir` **不**注入所加目录的 CLAUDE.md（只注入 `~/.claude/CLAUDE.md`）→ 记忆**只能**显式注入
- 🟢 Fish TTS 免费档首包中位 **~1.25s**；`model` **必须放 HTTP header**（放 body 会静默掉回付费模型 → 402）
- 🟢 SenseVoice 对**任何非语音**都会"幻觉"出文本（静音 → `그。`、白噪声 → `Yeah.`）→ 文本层过滤无效，只能在**音频层**拦
- 🟢 MCP 热重连（`mcp_reconnect` 控制帧）有效，**不用重启脑进程**。⚠️ **这是非官方通道，升级 Claude Code 后必须回归测试**
- 🔴 综合情绪识别（表情 + 语气 + 环境）**无官方榜单**，属推断，需自测

## 10. 踩过的坑（红线，改代码前先看）

1. **杀进程必须用 `./jarvis.sh`**。macOS 上真实进程名是 `.../MacOS/Python`（**大写 P**），`pkill -f "python -m jarvis_voice"` **永远匹配不到**，只杀掉 zsh 包装，留下**孤儿实例继续抢麦克风**。真机踩过：同时跑 3 个，对着旧代码说话还以为新功能没生效。
2. **`--resume` 是链式的、很危险**。每次恢复继承上一次全部上下文 → 任何污染过的会话都会永久烘焙进链条。**真机踩过两次**（助手带着测试对话的记忆醒来）。清理必须从 `--fresh` 起。
3. **别用 `print` 调试实时音频路径**。`Player._cb` 是实时线程。
4. **`--bare` 下没有 WebSearch / WebFetch / Write**。工具集是刻意的最小集（启动快），搜索走 Tavily MCP。
5. **Fish 的 `model` 必须放 HTTP header**，放 body 会静默掉回付费模型 → 402。
6. **SenseVoice 对任何非语音都会幻觉出文本**（静音→`그。`、白噪声→`Yeah.`）。文本层过滤无效，只能在**音频层**拦（见 `vad.py` 信噪比门限）。
7. **`--add-dir` 在 `--bare` 下不注入所加目录的 CLAUDE.md**（注的是 `~/.claude/CLAUDE.md`——那是编码指令，对语音脑是污染）。
8. 🆕 **跑 `tests/` 会真实出声**（2026-09-18 实测踩到）：`test_orchestrator.py`（播填充音 + TTS）和 `test_spoken_style.py`（调 Claude + TTS 真朗读）会驱动扬声器。**跑测试前先确认音量/戴耳机**，别在安静环境或会议中跑。
9. **填充音必须用独立的 TTS 实例**，不复用 `self.tts`：`FishTTS._ws_client` 是共享单例，启动预渲染线程与 TTSThread 同时调 `synthesize` 会交错损坏 WebSocket 流（审计发现）。加锁更糟（预渲染会阻塞延迟敏感的 TTS 线程）。
